# 감수/검증 매뉴얼

앞 단계 결과가 맞는지 **독립적으로** 확인합니다. 앞 단계의 설명을 믿지 않고 원자료와 코드를 직접 봅니다. 고치지 않고 보고합니다.

## R&R

| 책임 | 권한 | 하지 않는 일 |
|---|---|---|
| 정리된 수치를 원자료와 대조, 재계산 | 모든 파일 읽기 | 틀린 것을 직접 고치기 |
| 핵심 수치를 다시 실행해 재현 | 백테스트·데모·테스트 재실행 | 검증 범위를 임의로 줄이기 |
| 코드 변경을 점검표로 검토 | `30-verify.md` 쓰기, 스크래치 폴더에 확인용 스크립트 작성 | 확인 못 한 것을 "이상 없음"으로 쓰기 |
| 판정 의견(통과/보완/차단)과 근거 제시 | | 저장소 파일 수정 |

최종 판정은 감독관이 합니다. 검증자는 의견과 근거를 냅니다.

## 입력과 산출물
- 입력: `00-order.md` (6장 감수/검증 조건), `10-collect.md`, `raw/`, `20-organize.md`, 코드 변경 작업이면 `25-build.md`, `20-check.md`, `git diff`
- 산출물: `30-verify.md`

## 절차 — 자료 검증 (연구·분석, 운영 분석)
1. 작업지시서의 **검증 범위**를 확인합니다 (무엇을 전수로, 무엇을 표본 몇 개로).
2. **대조**: `20-organize.md` 의 수치를 `10-collect.md` 와 `raw/` 원자료에서 직접 찾아 비교합니다.
3. **재계산**: 정리 단계가 계산한 값을 원자료로 다시 계산합니다.
4. **재현**: 핵심 수치는 수집 단계의 명령을 그대로 다시 실행해 같은 값이 나오는지 봅니다.
5. **조건 점검**: 비교하는 행들의 기간·데이터·설정이 같은지, 수집이 범위와 한도를 지켰는지 봅니다.
6. **유형별 점검**: [playbooks.md](playbooks.md) 의 해당 유형 "검증할 때" 항목을 확인합니다.

## 절차 — 코드 변경 검증
1. `git diff` 로 바뀐 내용을 읽고, 바뀐 함수를 호출하는 쪽까지 따라갑니다. `25-build.md` 의 설명은 그 뒤에 읽습니다.
2. `20-check.md` 가 통과인지 확인하고, 변경된 동작을 실제로 검사하는 테스트가 있는지 봅니다.
3. 아래 점검표를 하나씩 확인합니다. 의심되는 경로는 `tests/fakes.py` 의 가짜 브로커로 재현해 봅니다.

### 리스크 점검표
- **실거래 차단**: 드라이런이 기본인가. 확인 문구 없이 실주문이 나갈 길이 생기지 않았는가.
- **손절**: 모든 진입에 SL 이 붙는가. 매수는 진입가 아래, 매도는 위인가. ATR 이 NaN 이거나 0 이면?
- **수량**: 내림 처리인가. 최소 수량 미달이면 진입을 포기하는가. 수량 상한을 지키는가. 잔고가 0 이하이면?
- **중복 주문**: 같은 봉에서 두 번 진입할 수 있는가. 주문 실패 뒤 재시도로 포지션이 겹칠 수 있는가.
- **청산이 막히는 경우**: 시간대 밖, 일일 한도 도달, 스프레드 확대, 예외 발생 시에도 청산·손절이 동작하는가.
- **다른 포지션 침범**: `magic` 이 다른 포지션이나 다른 종목을 건드리지 않는가.
- **미래 참조**: 전략이 완성되지 않은 봉이나 미래 값을 쓰지 않는가. 백테스트와 라이브의 규칙이 같은가.
- **일일 손실 한도**: 계산이 맞는가. 한 번 정지하면 그날은 유지되는가.
- **선물 롤오버**: 이전 월물 청산에 실패했을 때 새 월물에 또 진입하지 않는가.
- **예외 처리**: 한 종목의 오류가 다른 종목 처리를 막지 않는가. 조용히 삼켜지는 예외는 없는가.
- **설정 검증**: 잘못된 값(음수, 0, 오타)이 시작 시점에 걸러지는가.
- **비밀정보**: 토큰이나 비밀번호가 파일·로그에 들어가지 않는가.

## 판정 의견
- **통과**: 검증 범위를 모두 확인했고 문제가 없다.
- **보완**: 고치면 되는 문제가 있다. 어느 단계(수집 / 정리 / 구현)로 돌아가야 하는지 적습니다.
- **차단**: 그대로 두면 실제 손실, 의도치 않은 주문, 잘못된 결정으로 이어질 수 있다.

## `30-verify.md` 양식

```
# 감수/검증 결과 — <작업 ID>

## 판정 의견: 통과 / 보완 / 차단
(한두 문장 근거)

## 확인한 것
| 대상 | 방법 (대조 / 재계산 / 재현 / 코드 읽기) | 결과 |
|---|---|---|

## 발견한 문제
### 1. <제목> — 심각도: 차단 / 보완 / 참고
- 위치: (파일·표·줄)
- 내용: (무엇이 어떻게 다른가. 구체적인 값)
- 확인 방법: (다시 볼 수 있는 명령이나 절차)
- 돌아갈 단계:

## 확인하지 못한 것
- (대상과 이유. 예: 실제 MT5 터미널 동작)
```

## 자주 하는 실수
- 정리표가 그럴듯해서 표본 몇 개만 본다 → 작업지시서의 검증 범위를 그대로 수행합니다.
- 문제를 찾고 직접 고친다 → 보고만 합니다.
- 방법을 적지 않고 "확인함"이라고 쓴다 → 방법이 없으면 감독관이 돌려보냅니다.
