# 작업 유형별 지침

단계별 매뉴얼은 모든 작업에 공통입니다. 여기에는 유형마다 달라지는 내용을 적습니다. 감독관은 작업지시서를 쓸 때, 각 역할은 자기 단계를 할 때 해당 유형을 읽습니다.

---

## A. 전략 연구 (`research`)

백테스트로 전략이나 파라미터를 비교하고, 채택할 만한지 근거를 만듭니다.

### 작업지시서를 쓸 때 (감독관)
- **시작 조건**: 실제 과거 봉 데이터 CSV 가 있다. 없으면 시작하지 않고 사용자에게 알립니다. 가상 시세로 대신하지 않습니다.
- 데이터 기간을 **앞 70%(탐색) / 뒤 30%(검증)** 로 나누는 날짜를 지시서에 적습니다.
- 비교할 설정 목록과 백테스트 횟수 한도를 정합니다. 조합이 많으면 한도 안에서 우선순위를 정합니다.
- 채택 기준(기본값, 지시서에서 바꿀 수 있음): 검증 구간에서 **거래 100건 이상, Profit Factor 1.2 이상, 최대낙폭 15% 이하**.
- 사용자 승인 사항: 전략·파라미터 채택과 설정 반영.

### 수집할 때
- 파라미터는 **탐색 구간에서만** 비교합니다. 검증 구간은 지시서가 지정한 설정에 대해 **한 번만** 돌립니다.
- 설정 사본은 `raw/` 에 두고, 실행마다 설정 파일·기간·전략 옵션·결과 파일을 적습니다.
- `symbols[].backtest` 의 `contract_size`, `spread`, `commission_per_lot` 값을 함께 기록합니다.

### 정리할 때
- 열: 설정 / 구간(탐색·검증) / 거래수 / 승률 / PF / 순손익 / 최대낙폭(%) / 비상손절 횟수.
- 탐색 구간과 검증 구간의 수치를 같은 설정끼리 나란히 놓습니다.

### 검증할 때
- 탐색·검증 기간이 겹치지 않는가. 검증 구간을 여러 번 돌려 고른 흔적은 없는가.
- 채택 기준 세 가지를 수치로 대조합니다.
- 수익이 소수의 거래에 몰려 있지 않은가 (`raw/` 의 거래 CSV 에서 상위 5건 비중).
- 이웃한 파라미터 값에서도 비슷한가. 스프레드를 1.5배로 올려도 버티는가. (수집에 없으면 "확인하지 못함")
- 백테스트 비용 설정이 실제 브로커 값인지 알 수 없으면 금액 수치는 참고용이라고 적습니다.

### 알아둘 백테스트 가정
- 종가 신호 → 다음 봉 시가 체결, 고정 스프레드, 비상 손절은 봉 고가/저가로 체크.
- 일일 손실 한도와 스프레드 필터는 백테스트에 반영되지 않습니다.
- 매매 시간대는 `session_timezone: server` 일 때만 반영됩니다.

## B. 운영 분석 (`ops`)

봇의 운영 기록을 읽고 기간 성과와 이상 징후를 정리합니다.

### 작업지시서를 쓸 때 (감독관)
- **시작 조건**: `logs/trades.csv` 와 `logs/bot.log` (데모는 `logs/demo_trades.csv`) 가 있다. 운영 PC 의 기록은 저장소에 없으므로, 없으면 사용자에게 가져와 달라고 요청합니다.
- 분석 기간과 모드(DRY-RUN / LIVE / DEMO)를 정합니다. 서로 섞지 않습니다.
- 아래 "정리할 때"의 기본 항목(요약, 종목·전략별 표, 이상 징후 목록) 중 이번에 뺄 것이 있으면 지시서에 "제외"라고 적습니다.

### 거래 기록 파일의 특성 (`trades.csv`, `demo_trades.csv`)
- `time` 열은 **기록한 시점의 시계 시각**입니다. 데모에서는 가상 시세의 봉 시각이 아니라 실행한 시각이 찍힙니다. 봉 시각 열은 없습니다.
- 청산 행(`close`, `stop`)의 `key` 는 빈칸입니다. 진입 행과는 `ticket` 으로 짝짓습니다.
- `profit` 은 청산 행에만 있고 부동소수 표기 그대로입니다. 파일 맨 앞에 UTF-8 BOM 이 있습니다(`utf-8-sig` 로 읽기).
- 데모 실행은 `logs/demo_trades.csv` 를 매번 새로 씁니다. 집계 전에 `raw/` 로 복사합니다.

### 수집할 때
- 기간 내 거래 기록 전체, 로그의 오류·경고 줄, 아래 이상 징후에 해당하는 줄을 발췌해 `raw/` 에 둡니다.

### 정리할 때
- 요약: 거래 수, 승률, 순손익, 가장 큰 손실.
- 종목·전략별 표: 거래 수, 승률, 손익.
- 이상 징후 목록(근거가 되는 로그 줄과 함께):
  주문 실패·반복 오류·재접속 / 비상 손절이나 "서버측 청산" 급증 / 일일 손실 한도 도달 /
  스프레드·시간대로 보류된 진입 다수 / 같은 종목에서 짧은 시간에 진입·청산 반복 / 수량 부족으로 포기한 진입.

### 검증할 때
- 거래 수와 손익 합계를 거래 기록 CSV 에서 다시 계산합니다.
- 이상 징후로 든 로그 줄이 실제로 있는지, 기간 안의 것인지 확인합니다.

### 보고할 때
- 거래 30건 미만이면 승률·손익으로 전략을 평가할 수 없다고 적습니다.
- 원인을 추정할 때는 추정이라고 밝힙니다.

## C. 코드 변경 (`code`)

기능 추가, 버그 수정. 단계는 (필요하면 수집·정리) → 구현 → 감수/검증 → 최종검토 보고입니다.

### 작업지시서를 쓸 때 (감독관)
- 영향 범위를 먼저 알아야 하면 수집 단계에서 관련 코드와 호출 관계를 모으게 합니다. 단순한 변경이면 수집·정리를 생략하고 `status.md` 에 생략 사유를 남깁니다.
- 구현 조건에 "바꿀 범위"와 "바꾸지 않을 것"을 적습니다.
- 구현 게이트는 감독관이 `python tools/check.py --out <폴더>/20-check.md` 를 직접 돌려 판정합니다.
- 아래 파일이 바뀌면 검증 범위에 **리스크 점검표 전체**를 넣습니다:
  `engine.py`, `broker.py`, `sizing.py`, `sessions.py`, `strategies.py`, `config.py`, `backtest.py`, `run_bot.py`
- 사용자 승인 사항: main 병합, 데모 회귀 기준값 변경.

### 구현할 때 → [developer.md](developer.md)
### 검증할 때 → [verifier.md](verifier.md) 의 "코드 변경 검증"과 리스크 점검표
