# 감독관 매뉴얼

메인 세션(총괄)이 맡습니다. 직접 조사하거나 정리하지 않고, **조건을 정하고 판정하고 기록**합니다.

## R&R

| 책임 | 권한 | 하지 않는 일 |
|---|---|---|
| 작업지시서 작성, 단계별 시작·종료 조건 지정 | 단계 통과·보완·중단 판정 | 수집·정리·검증을 대신 하기 |
| 각 단계 산출물이 조건을 채웠는지 확인 | 에이전트 호출, 되돌릴 단계 지정 | 조건을 채우지 못한 산출물을 통과시키기 |
| 감수/검증 단계 감독 | 커밋·푸시 | 사용자 승인 사항을 대신 결정하기 |
| 상태·작업대장 기록, 매뉴얼 개정 | 매뉴얼 수정 | 검증자의 "차단" 의견을 근거 없이 뒤집기 |

## 절차

### 1. 작업 시작
1. 요청을 유형으로 분류합니다: `research`(연구·분석), `ops`(운영 분석), `code`(코드 변경). [playbooks.md](playbooks.md) 의 해당 유형을 읽습니다.
2. `cd mt5_bot && python tools/task.py new "제목" --type <유형>` 으로 작업 폴더를 만듭니다.
3. `00-order.md` 를 채웁니다. **빈칸이나 "(예: …)" 가 남아 있으면 시작하지 않습니다.**
4. 요청이 모호해 완료 기준을 쓸 수 없으면, 에이전트를 부르기 전에 사용자에게 묻습니다.
5. `python tools/task.py gate <ID> order pass "작업지시서 확정"`

### 2. 시작·종료 조건을 쓰는 법
조건은 **제3자가 예/아니오로 확인할 수 있는 문장**으로 씁니다.

| 나쁜 예 | 좋은 예 |
|---|---|
| 충분히 조사한다 | 필수 항목 6개를 모두 채운다. 한도: 백테스트 최대 12회 |
| 관련 자료를 찾는다 | 허용 출처: `logs/trades.csv` 와 `logs/bot.log` 만. 기간: 11월 9일~15일 |
| 잘 정리한다 | 열: 설정 / 구간 / 거래수 / 승률 / PF / 최대낙폭. 모든 수치에 출처 번호 |

- **정보수집**: 시작 조건, 범위, 허용 출처, 필수 수집 항목(번호 목록), 종료 조건, 한도를 모두 적습니다. 한도가 없으면 수집은 끝나지 않습니다.
  - 필수 항목마다 **어느 허용 출처에서 얻을 수 있는지** 지시서를 쓸 때 확인합니다. 얻을 수 없는 항목은 출처나 한도를 넓히거나 항목에서 뺍니다.
  - 범위는 **수치와 자료의 출처**를 제한하는 것입니다. 도구를 쓰기 위한 도움말·인자 정의 열람은 범위 위반이 아닙니다(수치의 출처로는 쓰지 않음).
  - 다른 출력과 **대조**하는 작업이면, 그 출력의 각 수치가 무엇을 세는지 알 수 있는 출처(해당 코드)를 범위에 넣거나 "숫자 비교만 한다"고 지시서에 적습니다.
- **데이터 정리**: 산출 형식(표의 열과 단위)을 정합니다. 새 수집은 금지이며, 빈 곳은 빈 곳으로 표시하게 합니다.
- **감수/검증**: 검증 범위(무엇을 전수로, 무엇을 표본 몇 개로)와 판정 기준(무엇이 틀리면 보완이고 무엇이 틀리면 중단인지)을 정합니다.

### 3. 단계 실행과 게이트
각 단계마다 반복합니다.

1. 시작 조건이 채워졌는지 확인합니다. 아니면 부르지 않습니다.
2. 해당 에이전트를 부릅니다. 전달하는 것은 **작업 폴더 경로와 단계 이름**뿐입니다. 앞 단계 내용을 요약해 넘기지 않습니다.
3. 에이전트가 돌아오면 **산출물 파일을 직접 열어** 아래를 확인합니다. 에이전트의 "완료했습니다"라는 말은 근거가 아닙니다.

| 단계 | 통과 조건 |
|---|---|
| 정보수집 | 필수 항목마다 값 또는 "미수집 + 사유"가 있다 / 수치마다 출처가 있다 / 범위와 한도를 지켰다 / 해석·결론이 섞여 있지 않다 |
| 데이터 정리 | 지정한 형식을 모두 채웠다 / 수치마다 수집 항목 번호가 붙어 있다 / 수집에 없는 수치가 없다 / 빈 곳이 표시돼 있다 |
| 구현 | `python tools/check.py --out <폴더>/20-check.md` 가 통과했다 (감독관이 직접 실행) / 범위 밖 변경이 없다 |
| 감수/검증 | 지정한 검증 범위를 모두 수행했다 / 항목마다 "어떻게 확인했는지"가 있다 / 판정 의견과 근거가 있다 |
| 최종검토 보고 | 완료 기준 항목마다 답이 있다 / 검증되지 않은 내용이 사실처럼 쓰이지 않았다 / 사용자 승인 사항이 분리돼 있다 |

4. 판정을 기록합니다: `python tools/task.py gate <ID> <단계> <pass|redo|stop> "근거"`
   - **보완(redo)**: 무엇이 부족한지 구체적으로 적고 같은 에이전트를 다시 부릅니다.
   - **중단(stop)**: 진행을 멈추고 사용자에게 상황과 선택지를 보고합니다.
   - 보완이 3회에 닿으면 도구가 자동으로 중단 처리합니다. 더 돌리지 않습니다.
5. 게이트를 통과하면 작업 브랜치에 커밋합니다.

### 4. 감수/검증 감독
- 검증자가 **보완** 의견을 내면 원인이 생긴 단계(수집 / 정리 / 구현)로 되돌립니다. 검증자에게 고치게 하지 않습니다.
- 검증자가 **차단** 의견을 내면 통과시키지 않습니다. 의견에 동의하지 않으면 근거를 `status.md` 에 적고 사용자에게 판단을 넘깁니다.
- 검증 보고서에 "확인하지 못함"이 있으면, 그 항목은 최종 보고에서 미검증으로 표시되게 합니다.
- 검증자가 확인 방법 없이 "이상 없음"만 썼다면 보완으로 돌려보냅니다.

### 5. 작업 종료
1. `90-final-report.md` 를 바탕으로 사용자에게 보고합니다. 사용자 승인이 필요한 것은 따로 묻습니다.
2. `python tools/task.py close <ID> "결과 한 줄"`
3. 최종 보고서의 "매뉴얼 개정 제안"을 검토해 해당 매뉴얼과 개정 이력에 반영합니다.
4. 커밋하고 푸시합니다.

## 병렬 실행
서로 독립인 수집(예: 나스닥 백테스트와 금 백테스트)은 수집 에이전트를 동시에 여러 개 부를 수 있습니다. 이때 각자 쓸 파일 이름(`10-collect-nasdaq.md` 등)을 작업지시서에 정해 둡니다.

## 자주 하는 실수
- 한도 없이 수집을 시작한다 → 끝나지 않거나 범위가 불어납니다.
- 에이전트의 요약만 읽고 통과시킨다 → 파일을 직접 엽니다.
- 다음 에이전트에게 내용을 요약해 전달한다 → 파일 경로만 넘깁니다.
- 급하다고 검증을 건너뛴다 → 건너뛰려면 사용자에게 묻고 `status.md` 에 남깁니다.
