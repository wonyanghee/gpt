# 구현(봇 개발자) 매뉴얼

코드 변경 작업에서만 쓰는 단계입니다. 작업지시서가 정한 범위의 코드를 고치고 테스트를 씁니다.

## R&R

| 책임 | 권한 | 하지 않는 일 |
|---|---|---|
| 지시 범위의 코드 구현·수정 | `mt5_bot/` 코드와 테스트 수정 | 범위 밖 리팩터링 |
| 바뀐 동작을 확인하는 테스트 작성 | `tools/check.py`, `pytest`, 데모 실행 | 테스트를 느슨하게 고쳐 통과시키기 |
| 설정 항목이 바뀌면 예시 설정과 README 갱신 | `25-build.md` 쓰기 | 운영 설정 수정, 실거래 확인 절차 약화 |
| 자동 검사 통과 확인 | | 커밋·푸시 |

## 입력과 산출물
- 입력: `00-order.md` (5장 구현 조건), 있으면 `10-collect.md`, `20-organize.md`
- 산출물: 코드 변경, `25-build.md`

## 코드 구조
- `indicators.py` 지표 / `strategies.py` 전략 / `engine.py` 매매 엔진 / `broker.py` MT5·드라이런 브로커
- `sizing.py` 수량 / `sessions.py` 시간대 / `backtest.py` 백테스트 / `sim.py` 시뮬레이션 / `config.py` 설정 검증

## 반드시 지키는 불변 조건
- **전략은 완성된 봉만 봅니다.** 미래 데이터를 참조하지 않습니다. 상위봉은 `align_to_base` 로 붙입니다.
- **라이브와 백테스트는 같은 전략 코드**를 씁니다. 엔진의 진입·청산 규칙을 바꾸면 `backtest.py` 도 같은 규칙이 되게 합니다.
- **모든 진입 주문에는 비상 손절(SL)이 붙습니다.**
- **수량은 내림**하고, 최소 수량으로도 위험 한도를 넘으면 진입하지 않습니다.
- **청산과 손절은 어떤 필터로도 막지 않습니다.** 시간대·일일 한도·스프레드 필터는 신규 진입에만 적용합니다.
- **봇 주문은 `magic` 으로만 식별**합니다. 다른 포지션을 건드리지 않습니다.
- **기본은 드라이런**입니다.
- 주문 실패는 알림을 보내고 넘어갑니다. 같은 봉에서 자동으로 재주문하지 않습니다.
- 새 설정값은 `config.py` 에서 검증하고, 기본값은 기존 동작과 같게 둡니다.

## 절차
1. 고치기 전에 관련 코드와 테스트를 읽습니다.
2. 지시 범위만 고칩니다.
3. 바뀐 동작마다 테스트를 추가합니다. MT5 없이 도는 가짜 브로커(`tests/fakes.py`)를 씁니다. 경계값(0, 음수, NaN, 최소 수량 바로 아래, 주문 거부)을 우선합니다.
4. `cd mt5_bot && python tools/check.py` 를 돌립니다. 데모 회귀 기준값이 달라졌다면:
   - 전략·엔진을 의도적으로 바꾼 것이면 `tools/baseline.json` 을 고치고 `25-build.md` 에 사유와 이전·이후 값을 적습니다.
   - 의도한 것이 아니면 회귀입니다. 원인을 찾아 고칩니다.
5. `25-build.md` 를 씁니다.

## `25-build.md` 양식

```
# 구현 결과 — <작업 ID>

## 바꾼 것
| 파일 | 내용 | 이유 |
|---|---|---|

## 추가한 테스트
- <테스트 이름>: 무엇을 확인하는가

## 자동 검사
- tools/check.py 결과: 통과 / 실패 (실패 시 내용)
- 기준값 변경: 없음 / 있음 (사유, 이전 → 이후)

## 리스크에 영향이 있는 부분
- (주문·손절·수량·설정 검증 중 건드린 것. 없으면 "없음")

## 확인하지 못한 것
- (예: 실제 MT5 터미널 동작, Windows 전용 동작)
```
